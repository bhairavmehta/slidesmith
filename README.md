# slidesmith

Beautiful, consistent slide decks (`.pptx`) and documents (`.docx`) generated by an LLM
agent — with the agent (Kiro) doing the thinking and this toolchain doing the pixels.

```
            Kiro (LLM agent)                         slidesmith (deterministic)
 ┌──────────────────────────────────┐      ┌───────────────────────────────────────────┐
 │ 1 understand + gather material   │      │                                           │
 │ 2 storyline: action titles       │      │  validate  (pydantic schema)              │
 │ 3 write  name.deck.json ─────────┼─────▶│  render    (layout archetypes + tokens,   │
 │                                  │      │             text sized with font metrics) │
 │ 5 critique PNGs with rubric ◀────┼──────│  rasterize (MS Office export → PNG)       │
 │ 6 edit spec, rebuild (≤ 3 rounds)│      │  lint      (overflow, density, titles,    │
 │ 7 deliver                        │      │             chart sanity, contrast …)     │
 └──────────────────────────────────┘      └───────────────────────────────────────────┘
        steering files in .kiro/                MCP server or CLI
```

Why it looks good: the LLM never chooses a font size, colour or coordinate. It picks a
**layout archetype** and writes the **words**; the theme's design tokens and the renderers
decide everything visual. Overflow is measured with real font metrics at build time and
reported back as an error to fix by cutting words — not hidden by shrinking type.

## Windows 11 quick start (no admin rights)

1. **Python 3.10+** for your user, if you don't have it:
   `winget install -e --id Python.Python.3.12 --scope user` (or Company Portal / Software Center).
2. Unzip slidesmith somewhere permanent, e.g. `C:\Users\<you>\tools\slidesmith`.
3. Double-click **`install.cmd`** (or run it in a terminal). It:
   - creates a private `.venv\` and pip-installs everything (python-pptx, python-docx,
     matplotlib, **pywin32**, **pypdfium2**, mcp) — nothing system-wide;
   - writes `slidesmith.cmd` next to it;
   - registers the `slidesmith` MCP server and copies the steering files into
     `%USERPROFILE%\.kiro\` so they work in **every Kiro workspace** (existing `mcp.json`
     is merged and backed up to `mcp.json.bak`);
   - runs `slidesmith doctor`, which checks PowerPoint/Word over COM and does a test build.
4. Restart Kiro (or reconnect MCP servers in the Kiro panel). In chat:
   > #slidesmith-workflow Build a 10-slide deck for the leadership review from notes.md

**First time? Follow [FIRST-RUN.md](FIRST-RUN.md)** — a 20-minute checklist that proves it
works on your machine before you rely on it.

Options: `install.cmd --workspace C:\work\project` (also configure that workspace),
`--no-user-kiro`, `--index-url https://<corp-mirror>/simple` (pip behind a proxy),
`--offline` (reuse packages IT already installed), `--no-venv` (AppLocker blocks
python.exe copies in your user folder), `--uninstall`. The installer warns if the folder
is inside OneDrive or has a very long path — both break pip on Windows.

If something looks off later, run `slidesmith.cmd doctor` — every line is `[ OK ]`,
`[WARN]` or `[FAIL]` with the fix next to it.

Windows specifics handled for you:
- Office is driven in a **separate process with a timeout** (default 240 s,
  `SLIDESMITH_OFFICE_TIMEOUT`). If PowerPoint/Word is stuck on a sign-in, activation or
  recovery dialog, the build falls back to the built-in preview instead of hanging Kiro,
  and the report tells you to open Office once and dismiss the dialog.
- If the previous deck is **still open in PowerPoint** (Windows locks it), the build writes
  `name (2).pptx` and says so instead of failing.
- UTF-8 everywhere: specs saved by Notepad (with BOM) load; output is safe in cp1252
  consoles and Kiro's terminal.
- Your open PowerPoint is reused and left open; Word runs as a private hidden instance.

## Install on other systems

Only pip packages, no admin rights and no system installs:

```bash
python install.py                 # same as install.cmd: venv + Kiro wiring + doctor
# or manually:
pip install -e ".[mcp,office]"    # office = pywin32 (Windows only) + pypdfium2
```

## Who draws the review images

The agent's visual check needs page images. `build` picks the best renderer available
(`--renderer auto`, the default) and records which one ran in the report:

| Renderer | Needs | Fidelity |
|---|---|---|
| `office` (first choice) | Microsoft PowerPoint + Word on the machine. Windows: drives them over COM via `pywin32`. macOS: AppleScript. | Exact — Office itself exports each slide to PNG; Word exports a PDF that `pypdfium2` rasterizes. |
| `libreoffice` | LibreOffice, if it happens to be installed | Close |
| `preview` | nothing (pure Python) | Same geometry and font metrics as the renderer; doc pagination approximate. Used on CI or when Office isn't available. |

Notes for the Office path:
- Office runs headless — no windows open. A PowerPoint you already have open is reused
  and left running; Word runs as a private instance and quits after the export.
- The first time on macOS, Office may ask for permission to be controlled by your
  terminal/Kiro (System Settings → Privacy & Security → Automation). Allow it once.
- Force a renderer with `--renderer office|libreoffice|preview` (CLI) or the `renderer`
  argument of the MCP `build` tool.

Fonts: the `default` theme uses **Calibri**, which every Office install has. The `warm`
theme uses **Inter**; install it (user-level install is fine) where the files are opened,
otherwise Office substitutes a font and the `office` renderer will show the reflow.

## Hook it into Kiro (manual — the installer already does this)

1. Copy `.kiro/` into your Kiro workspace root (or open this repo as the workspace).
   - `.kiro/settings/mcp.json` registers the `slidesmith` MCP server. Point `command` at
     the Python environment where you installed the package.
   - `.kiro/steering/slidesmith-workflow.md` — the loop (manual: reference it with
     `#slidesmith-workflow` in chat).
   - `.kiro/steering/slidesmith-design.md` — storytelling, layout choice, writing rules.
   - `.kiro/steering/slidesmith-critique.md` — the visual rubric for the inspect step.
     Both load automatically whenever a `*.deck.json` / `*.doc.json` file is in play.
2. Ask, for example:
   > #slidesmith-workflow Build a 10-slide deck for the steering committee from
   > `q3-results.xlsx` and `notes.md`. Audience: VPs, 20 minutes, we need a go/no-go.

Kiro will write `steering-committee.deck.json`, call `build`, look at the pages with
`view_pages`, fix, and hand you `build/steering-committee/steering-committee.pptx`.

No MCP? The steering works with the CLI too — Kiro can run the commands in its terminal.

## CLI

```bash
slidesmith schema deck > deck.schema.json     # the contract the LLM writes against
slidesmith themes
slidesmith validate examples/ai-eval-program.deck.json
slidesmith build examples/ai-eval-program.deck.json            # -> examples/build/ai-eval-program/
slidesmith build examples/release-gating-memo.doc.json --theme warm
slidesmith doctor                                              # is this machine ready?
```

(On Windows after `install.cmd`, use `slidesmith.cmd` in the install folder, or
`.venv\Scripts\slidesmith.exe`.)

`build` writes `<name>.pptx|docx`, `<name>.pdf` (office/libreoffice renderers),
`pages/page-NN.png`, `contact_sheet.png`, `report.json` and `report.md`, and exits `2`
while errors remain (handy in CI).

## Spec in 20 lines

```json
{
  "kind": "deck",
  "title": "Q3 Program Review",
  "theme": "default",
  "footer": "Internal",
  "slides": [
    { "layout": "title", "kicker": "Q3 2026", "title": "Evaluation now gates every release" },
    { "layout": "kpis", "title": "Coverage tripled while cost fell 71%",
      "items": [{ "value": "86%", "label": "traffic scored", "delta": "+61 pts" },
                { "value": "-71%", "label": "cost vs manual QA", "sentiment": "positive" }] },
    { "layout": "chart", "title": "Billing trails every other channel",
      "chart": { "type": "bar", "categories": ["Billing", "Orders"],
                 "series": [{ "name": "Score", "values": [0.61, 0.88] }],
                 "number_format": "0.00", "highlight": 0 },
      "takeaway": "Stale policy content explains most billing failures." }
  ]
}
```

Slide layouts: `title, section, bullets, two_column, big_number, kpis, chart, table,
timeline, quote, closing`. Document blocks: `heading, paragraph, bullets, callout, table,
chart, kpis, quote, page_break`. Inline `**bold**` and `*italic*` work in all text.
See `examples/` for complete specs that exercise every layout and block.

## Number provenance — no invented figures

List the files the content comes from in the spec:

```json
{ "kind": "deck", "title": "...", "sources": ["data/q3-metrics.xlsx", "notes.md"], "slides": [ ... ] }
```

Every number in the slides' text **and** chart data is then looked up in those files
(.xlsx, .csv, .md, .txt, .json, .docx, .pptx, .pdf). Formatting is tolerated — 86% ↔ 0.86,
$4.2M ↔ 4,200,000, 0.82 ↔ 0.8213 — but anything not found is reported as an
`unverified_figure` warning naming the slide and text. Derived numbers (differences,
ratios) are flagged on purpose so someone checks the arithmetic; the steering tells Kiro to
show the calculation in the speaker notes and to list every remaining flag in its final
message. (The sample deck shipped with a wrong "20 points" gap — this check caught it.)

## Tests

```
python tests/stress_test.py --renderer office   # hostile content, both themes; Office must open all of it
python tests/test_provenance.py                 # wrong numbers flagged, rounding accepted, all source types read
```

Every generated .pptx/.docx is also checked for schema validity (ISO/IEC 29500) during
development; each build re-opens its own output before reporting success.

## What the linter checks

| Rule | Example |
|---|---|
| `overflow` (error) | text can't fit its box even at the theme's minimum size |
| `schema` (error) | series length ≠ categories, missing fields, unknown layout |
| `number_format` (error) | `"0%"` with values like 42 (renders 4200%) |
| `action_title` | "Overview" instead of a sentence stating the point |
| `density`, `bullet_length` | > 5 bullets, > 25-word bullets, > 80 words per slide |
| `monotony`, `variety` | 3 same layouts in a row; > 50% bullet slides |
| `chart_type`, `chart_sort` | pie with 8 slices; unsorted single-series bars |
| `contrast` | theme colours below WCAG ratios |
| docs: `bluf`, `heading_levels`, `empty_section`, `paragraph_length`, `wall_of_text`, `orphan_page` | |

Score = 100 − 15·errors − 5·warnings − 1·info.

## Bring your brand

Copy `slidesmith/themes/default.json` to `mybrand.json`, change colours, fonts, sizes,
then `"theme": "path/to/mybrand.json"` (or drop it in `themes/`). Themes can
`"extends": "default"` and override only what changes. Run a build: the `contrast` rule
tells you if the palette is unreadable.

## Extending

- **New slide layout**: add a model to `schema.py` (and to the `Slide` union), a
  `_<layout>` method in `render_pptx.DeckRenderer`, and one line in the layout table in
  `slidesmith-design.md` so the agent knows when to use it.
- **New lint rule**: add it to `lint.py`; give it a `hint` the agent can act on.
- **Corporate .potx master**: the renderer draws on a blank layout. To use a client master,
  load it with `Presentation("brand.potx")` in `DeckRenderer.__init__`, delete its sample
  slides, and pick the blank layout by name — tokens should match the master's colours.

## Layout

```
slidesmith/
  schema.py        spec contract (pydantic → JSON Schema)
  theme.py         design tokens, colour helpers, contrast
  themes/*.json    default (Calibri, navy/coral), warm (Inter, cream/clay)
  textfit.py       font-metric text measurement and fitting
  render_pptx.py   11 slide archetypes, native editable charts, styled tables
  render_docx.py   Word styles, callouts, KPI cards, captions, numbered lists, page numbers
  charts_mpl.py    themed matplotlib charts for documents
  rasterize.py     renderer selection: Microsoft Office (COM / AppleScript), LibreOffice,
                   pure-Python preview; PDF → PNG via pypdfium2; contact sheet
  preview.py       pure-Python drawing of .pptx slides and doc pages (Pillow + matplotlib)
  lint.py          deterministic QA rules
  build.py         validate → render → rasterize → lint → report
  cli.py           command line
  mcp_server.py    MCP tools for Kiro: get_schema, list_themes, validate_spec, build, view_pages
  office_export.py PowerPoint/Word COM export, run as a timed child process
  doctor.py        `slidesmith doctor` health check
.kiro/             steering files + MCP config template
examples/          a full deck and a full memo
install.cmd        Windows launcher for install.py (finds Python, keeps window open)
install.py         per-user installer: venv, pip, launcher, Kiro config, doctor; --uninstall
```
